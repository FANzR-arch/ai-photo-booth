## 1\. 产品概述

### 1\.1 一句话定位

**一台放在门店里、顾客自助拍照、云端 AI 生成风格化人像、当场付费取图并可打印的线下照相亭。**

### 1\.2 产品背景与要解决的问题

线下照相馆/商场/活动现场的「拍照留念」需求长期存在，但传统形式有三个痛点：

|**痛点**|**现状**|**本产品的解法**|
|---|---|---|
|**形式单一**|大头贴机只能加贴纸和边框，出片「不像本人也不好看」|用生成式模型做人像风格化重绘，保留本人五官与年龄感|
|**人力成本高**|需要摄影师、修图师、收银员在场|全自助流程，店员只在补纸/故障时介入|
|**现场出片慢**|拍摄 \+ 修图 \+ 打印动辄 20 分钟以上|单张生成实测约 23 秒量级，流程内完成取图|

产品选择**生成式 AI 重绘**而非「美颜滤镜」作为核心差异点：

用户拿到的是「**另一个场景/媒介里的自己**」，而不是磨皮瘦脸后的原照。与此同时，产品把**人脸一致性**定为最高优先级约束，明确拒绝「统一瘦脸、美白、幼化」的网红脸路线。

### 1\.3 产品形态与运行形态

|**维度**|**当前形态**|
|---|---|
|**硬件载体**|一台 Mac（或 Windows PC）\+ USB 摄像头 \+ EPSON L805 系列打印机|
|**软件形态**|本地 Node 服务（Fastify）\+ 浏览器全屏页面（kiosk 模式），非桌面原生应用|
|**网络依赖**|生成必须联网（调用火山方舟 Seedream）；取图依赖店内 Wi\-Fi；局域网内不需要公网 IP|
|**数据位置**|全部落在本机 `data/` 目录（SQLite \+ 文件系统），不上云|
|**部署方式**|双击桌面「启动拍照亭\.command」（Mac）/ `启动拍照亭.cmd`（Windows）|

产品刻意选择「**浏览器 \+ 本地服务**」而非 Electron 封装，理由是：当前不需要公网部署，浏览器全屏已足够；等专用相机、打印机、支付终端定型后再评估桌面封装，避免 Demo 阶段过早背上维护成本。**【文档】** 对此有明确论证。

### 1\.4 三条页面与三类用户

|**路径**|**面向谁**|**职责**|
|---|---|---|
|`/`|现场体验者|主题选择、拍照、确认、等待生成、选图、付款、取图|
|`/admin`|本机操作员/店员|API 配置、摄像头选择、打印机设置、风格提示词编辑、生成记录、订单|
|`/pickup/:token`|顾客手机|仅查看并下载该 token 已解锁的照片|

前端路由是手写的 `location.pathname` 判断（`main.tsx`），未使用 react\-router：`path.startsWith('/pickup/')` → Pickup，`path === '/admin'` → Admin，其余一律 Booth。**【代码】**

### 1\.5 范围边界

**当前版本要做（In Scope）**

- 自助拍照 / 上传照片 → AI 生成 → 相纸编辑 → 模拟付费 → 手机扫码取图 的完整闭环

- 63 款启用模板的内容运营能力（后台可改提示词、封面、开关、尺寸）

- 单机设备管理：管理员密码、API 凭据、摄像头、打印机

- Mac 一键安装/启动/更新

**当前版本明确不做（Out of Scope）**

|**不做的事**|**状态**|**说明**|
|---|---|---|
|**真实支付**|未实现|方案已设计（微信 Native / 支付宝当面付），因用户要求暂缓|
|**公网取图**|未实现|首版只做店内 Wi\-Fi；不把本地拍照亭暴露到公网|
|**开机自启**|明确不做|不注册 LaunchAgent、不注册登录项|
|**多门店/云端统一管理**|未实现|ROADMAP 第 4 阶段|
|**本地 AI 推理**|未实现|全部依赖云端 API|
|**多张生成**|已收敛为 1 张<br>|拍照亭固定 `imageCount = 1`；`IMAGE_COUNT` 环境变量已失效|
|**会员/账号体系**|无|无登录、无历史照片库、无跨设备同步|

|**指标**|**定义**|**数据来源**|**当前基线**|
|---|---|---|---|
|**北极星：付费取图转化率**|已付款订单数 ÷ 完成生成的会话数|SQLite `order` / `session`|未能测算（支付为模拟）|

|**上游请求耗时分解**|`headersMs` / `bodyMs` / `decodeMs` / `downloadMs`|`generation-timing.jsonl` → `providerImages[]`|每次生成追加一行，可分析|
|**未知结果率**|`status='unknown'` ÷ 总任务|SQLite `session.status`|未统计，需重点监控（直接等于潜在重复计费风险）|

|**打印成功率**|`submitted` ÷ 打印任务|SQLite `print`|未统计|
|**照片自动清理准确率**|到期后文件确实被删除|代码保证 \+ 定时器每秒执行|已实现【代码】|

**指标缺口**：产品当前**没有前端行为埋点**（无 GA、无自建上报、无漏斗统计）。唯一的结构化数据是 `generation-timing.jsonl` 的生成计时与服务端 SQLite 记录。要做转化率分析，必须新增前端埋点或从 `order`/`session` 反推。**【代码】**

### 2\.3 成本约束

- **每次生成都真实消耗 API 额度**，且产品策略是「上游结果未知时禁止自动重试」——这是为了防止重复计费。

- **当前没有每日费用上限**（文档明确写「当前没有真实支付或每日费用上限」），唯一并发保护是「同一台设备同时只处理一个生成任务」，但**这不等于每日预算上限**。**【文档】**

- 现有流程是「先生成、后购买」，因此**未被购买的生成成本由门店承担**；无人值守营业前必须明确这笔成本的责任方。【待定】

### 3\.4 关键场景分支

- **顾客不满意想重拍**：确认页有「重新拍一张」，回拍照页，不消耗 API。

- **中途想换主题**：拍照页有「更换主题」，**保留当前会话与已拍照片**，不新建会话、不调用 `/end`。**【代码】**

- **生成中想先看别的**：可以返回照片库挑相纸、写文字，生成不中断；等待页也有完整边框编辑器。

- **生成失败**：保留原图，停止动画，提供「重新生成」（会再次调用 API，界面上明确提示）。

- **结果未知**：明确告知「结果暂时无法确认。为避免重复计费，不提供自动重试，请到工作台检查记录。」——**没有重试按钮**。

- **同一位顾客拍多张**：本轮照片库累积多张，可来回切换、分别购买。

### FR\-06 AI 生成（核心能力）· P0

#### FR\-06\.1 提示词编排

生成提示词由服务端统一拼装，前端**只传照片和一个 prompt**。拼装包含六部分：

|**顺序**|**内容**|**来源**|
|---|---|---|
|**1**|人脸身份约束|固定模板（保留五官、年龄感、实际人数）|
|**2**|主题视觉描述|模板 `prompt`（工作台可编辑）|
|**3**|动作与表情|已写入主题视觉提示词内|
|**4**|服装选择|`用户选择：保留原服装` 或 `用户选择：按主题换装` \+ `outfitPrompt`|
|**5**|人体结构约束|固定模板（不产生多余肢体、不交换面孔）|
|**6**|输出比例|由用户选择或模板固定|

**关键规则**

- `outfitPrompt`（换装搭配提示词）**仅在「按主题换装」时发送**；选「保留原服装」时绝不附带，测试对此有专门断言。**【代码】**

- 两种服装模式**都允许**按主题重新设计站姿、坐姿、头部朝向、手势、表情及合照站位；衣服是否更换**不再限制动作**。这是 2026\-09\-30 的重要决策调整（此前旧的「保持原姿态」约束已被 `pose-migration.json` 清理）。**【文档】**

- 成人礼模板走独立 `generationPreset=coming-of-age` 分支，直接使用完整海报提示词，**不附加**普通照片的禁字规则和可选服装规则。**【代码】**

- 提示词模板中若残留 `{{占位内容}}`，创建会话与开启模板都会被服务端拒绝。

#### FR\-06\.2 生成执行

|**需求**|**规则**|
|---|---|
|**生成张数**|固定 **1 张**|
|**并发**|同时只允许 **1 个**生成任务；已有任务时新请求返回 **429「设备正在处理上一张照片，请稍后再试」**|
|**幂等**|状态为 `generating`/`ready`/`partial` 时重复调用 **返回 200 现状**，不重复调用上游|
|**未知结果**|`unknown` 状态**硬阻断**，返回 409「上游结果未知，禁止重复提交以避免重复计费」|
|**明确失败**|`failed` 允许用户显式点「重新生成」重试|
|**超时**|单次上游请求 **180 秒**|
|**上游图片下载**|单独 45 秒超时，DNS 解析 10 秒超时|
|**响应大小限制**|JSON 上限 **36 MiB**，单图上限 **24 MiB**|
|**重试**|**不存在自动重试**，无退避、无重试计数|
|**生成中过期**|放弃结果，不落盘、不复活，计时日志记 `status: 'aborted'`|

#### FR\-06\.3 上游调用规格

|**项**|**值**|
|---|---|
|**接口**|`https://ark.cn-beijing.volces.com/api/v3/images/generations`|
|**模型**|`doubao-seedream-5-0-pro-260628`（实测运行值）|
|**请求体**|`{model, prompt, image: "data:image/jpeg;base64,...", size, response_format: "b64_json", watermark: false}`|
|**不传参数**|`sequential_image_generation`、`stream`|
|**图片获取**|优先 Base64；回退供应商 URL（白名单域名）|
|**requestId**|`x-request-id` 或 `x-tt-logid`|

**SSRF 防护**：URL 回退下载只允许 `volces.com` / `volccdn.com` / `byteimg.com` / `ibyteimg.com` 及其子域，必须 HTTPS 443、无凭据、禁止重定向，且 DNS 解析结果必须是公网 IPv4（私有网段、回环、链路本地全部拒绝）。对 `http://127.0.0.1`、`https://localhost`、`volces.com.evil.invalid` 等 5 类恶意 URL 有专门测试。**【代码】**

#### FR\-06\.4 错误语义（决定能否重试）

|**上游情况**|**语义**|**用户可见文案**|
|---|---|---|
|HTTP 5xx / 408|**unknown**|Seedream 请求失败（HTTP n），结果状态不确定，请核对上游记录。|
|HTTP 4xx（如 401）|known，可重试|Seedream 请求失败（HTTP n），请检查模型权限、额度或请求参数。|
|上游返回 `body.error`|known，可重试|Seedream 返回生成错误，请凭请求编号检查控制台。|
|返回空响应体|**unknown**|上游返回空响应；结果可能已生成。|
|缺 `data[0]`|**unknown**|未获得图片；请核对上游是否计费，暂不重复生成。|
|JSON 超限|**unknown**|上游响应超过大小限制；请检查生成记录。|
|网络中断/超时/解析失败|**unknown**|生成连接中断、超时或结果解析失败；任务可能已计费，请检查上游记录，勿直接重试。|
|`EACCES` 连接权限拒绝|known（**唯一确认未发出的失败**）|本机网络权限阻止了连接，生成请求未发出。请检查服务运行权限后重新生成。|
|凭据缺失|known，不发请求|请在设备设置中填写 API 密钥和模型 ID 并保存。|

**产品含义**：`unknown` 的文案是「不让用户重试」而不是「重试」。这是一条**反直觉但正确**的设计——宁可少赚一单，也不要替顾客重复付费。**【文档】**有明确论证。

### FR\-12 打印（Mac 直接打印）· P1

|**需求**|**规则**|
|---|---|
|提交方式|服务端合成完整成片 → 通过 macOS CUPS `lp` 提交到选定队列；**不打开系统打印对话框、不要求付款**|
|触发方式|用户**明确点击**「打印照片」才提交；**不在生图完成时自动出纸**|
|界面状态|「打印照片」→「正在提交…」→「已提交打印」|
|已提交展示|「已提交 \{n\} 张 · \{CUPS 任务号\}」|
|查询|「查询打印状态」（只读本地记录，**不回读 CUPS 队列**）|
|份数|整数 **1–5**，默认 1|
|适配|`contain`（完整保留，留白居中，默认）/ `cover`（裁切铺满）|
|标题|`SNAP-{sha256(sessionId:imageId) 前 12 位}`|

**at\-most\-once 语义（本功能最重要的设计）**

|**状态**|**含义**|**能否重试**|
|---|---|---|
|`preparing`|已受理，正在渲染合成图|服务重启 → 转 `failed`「准备打印时服务重启，未提交打印。」|
|`submitting`|已写出临时文件，即将调用 `lp`|服务重启 → 转 `unknown`「服务曾重启，请检查系统打印队列，勿重复打印。」|
|`submitted`|`lp` 返回可识别的 CUPS 任务号|终态|
|`failed`|渲染/准备阶段失败（未提交）|**可重试**|
|`unknown`|提交阶段出错，**无法确认**|**永不自动重试**|

**其他规则**

- 任务主键 = `sha256(sessionId:imageId)`，**同一张照片天然只提交一次**；重复点击、刷新、重新打开都不会重复出纸。

- 打印使用的边框与文字是**点击前已保存的版本**，不打印低清预览。

- 临时合成图存 `data/print-jobs/`，提交结束即删；异常退出的残留文件下次启动清理。

- 打印任务记录**不含完整照片或 API 密钥**。

- 打印接口仅本机可用，配置必须管理员登录。

- 必须显式勾选「已确认打印机里装的相纸与以上设置一致」才能保存配置。

- 驱动无法提供纸张选项时**停止配置，不猜规格**。

- 「已提交打印」**只代表 CUPS 接受任务，不代表纸已经出来**；首版没有自动故障重打和实体出纸传感确认。

**失败处理（原文）**

|**场景**|**处理**|
|---|---|
|提交前失败|可以重试|
|提交超时|标记「结果不确定」，不能自动重打|
|服务中断|标记「结果不确定」，不能自动重打|
|返回无法识别|标记「结果不确定」，不能自动重打|
|缺纸、卡纸、离线、暂停|系统设置 → 打印机与扫描仪 → 对应打印机 → 打印队列处理|

**现场配置现状**：队列为 `EPSON_L805_Series`，**相纸尺寸尚未确认**（多处文档标注）。不要把系统默认 A4 当成已装纸。**【文档】【待定】**

### FR\-14 空闲与超时管理 · P0

|**场景**|**倒计时**|**行为**|
|---|---|---|
|待机页且无照片库|**不计时**|永不自动结束|
|体验中（无生成任务）|**120 秒**|归零 → 自动结束本轮|
|体验中（有生成任务）|**300 秒**|归零 → 自动结束本轮|
|剩余 ≤ 20 秒|—|显示浮层「\{n\} 秒后结束本次体验」\+「我还在，继续」按钮|
|点「我还在，继续」|重置|重新计时（120 或 300）|
|活动检测|任意 `pointerdown` / `keydown`|刷新活动时间|

**结束时的动作**（`finish()`）：递增轮次令牌 → 清屏（清空照片、订单、二维码、选中项、相纸、文字）→ 清空照片库与 `snap-round` → 回待机页 → 对所有会话发 `/end`（410 视为成功）→ 若有失败提示「已清除屏幕内容；后台会话未能结束，请检查网络。」

**设计意图**：防止上一位顾客的照片留在屏幕上被下一位看到。这是**隐私红线**，不是体验优化。

### FR\-22 模板体系与迁移升级 · P0

**这是产品能持续迭代而不砸掉老数据的关键机制。**

|**文件**|**作用**|
|---|---|
|`config/styles/styles.json`|内置模板源（70 条），启动时导入 SQLite|
|`config/styles/retired-styles.json`|下线模板映射（当前 `{"natural": "business"}`）|
|`group-photo-migration.json`|旧版分组提示词哈希|
|`portrait-migration.json`|旧版人像提示词哈希|
|`wardrobe-migration.json`|旧版换装提示词哈希|
|`quality-migration.json`|旧版质量提示词哈希|
|`pose-migration.json`|姿态\+换装双路基线哈希|
|`scene-quality-migration.json`|逐字段基线，支持同一字段多个历史版本|

**升级策略（核心设计）**

> 只有当工作台里保存的内容**精确等于某个已发布旧版本的哈希**时，才被新版内置内容替换。

因此：

- 门店自己改过的提示词、名称、封面、开关**永远不被升级覆盖**。

- 版本号单调递增（`max(saved.version + 1, style.version)`），且**每次启动至多 \+1**（升级后哈希不再匹配 → 幂等）。

- **已生成的成片不重新生成**：会话里保存了模板快照 `snapshot`。

- 下线模板移入 `retired-style` 保留快照，历史会话仍能完成生成。

**保留的运营语义**：更换内置模板不需要门店做任何操作；门店的自定义永远优先。

## 5\. 状态机与业务规则

### 5\.1 Session 状态机

```Plaintext
created ──上传照片──▶ photographed ──提交生成──▶ generating
                            ▲                        │
                            │                   ┌────┴────┐
                        （可重拍）           成功成功   失败/未知
                                                 │        │
                                            ready/partial  failed ──用户显式重试──▶ generating
                                                          unknown ──✗ 禁止重试
任意状态 ──/end 或 到期清理──▶ ended
```

|**状态**|**含义**|**允许动作**|
|---|---|---|
|`created`|已创建，未上传照片|上传、结束|
|`photographed`|已上传照片|替换照片、生成、结束|
|`generating`|生成中|查询、结束（幂等返回，不重复提交）|
|`ready`|生成完成（张数达标）|下单、改相纸、打印、结束|
|`partial`|部分成功（`imageCount=2` 时可达）|同 ready|
|`failed`|明确失败|**可重试**|
|`unknown`|结果未知|**禁止重试**（防重复计费）|
|`ended`|已结束|普通访问返回 410|

**启动修复**：服务启动时所有 `generating` 强制转 `unknown`，错误文案「服务曾重启，上游结果未知；为避免重复计费，不自动重试。」

### 5\.2 Order 状态机

`pending` →（模拟支付）→ `paid` / `failed` / `cancelled`；`paid` 为**终态不可逆**。金额固定 990 分，`paymentMode = 'simulate'`。

### 5\.3 PrintJob 状态机

`preparing` → `submitting` → `submitted`；任一环节失败 → `failed`（可重试）或 `unknown`（不可重试）。

### 5\.4 幂等与防重复计费矩阵

|**操作**|**幂等键**|**重复调用行为**|
|---|---|---|
|提交生成|会话状态|`generating`/`ready`/`partial` → 200 返回现状，不调用上游|
|提交生成（未知）|`unknown` 状态|409 拒绝|
|创建订单|会话 \+ 图片集合 \+ 状态|返回已有订单|
|模拟支付|`order.status === 'paid'`|终态，不重复发 token|
|取图 token|`s.token ??=`|只生成一次|
|提交打印|`sha256(sessionId:imageId)`|已存在且非 failed → 直接返回|
|相纸保存|—|覆盖式 upsert|
|模板迁移|版本号 \+ 哈希匹配|每次启动至多升级一次|
|照片清理|`deletedAt`|二次调用无副作用|
|管理员首设密码|原子文件创建|并发只有一个成功|

### 5\.5 并发与队列

|**机制**|**实现**|
|---|---|
|生成并发|全局 `jobs` 集合，`size >= 1` 时返回 429|
|配置保存互斥|有生成任务或存在 `generating` 会话时 409|
|打印并发|独立 `tasks` 集合，非空时 409|
|管理员首设互斥|`pending` 标志，并发第二次 429|
|相纸保存串行|前端 `frameQueue` Promise 队列|
|关闭清理|清定时器 → 等待所有 job → 等待所有打印任务 → 关闭数据库|

### 5\.6 过期与清理

见 FR\-15。补充：`erasePhotos` 有目录安全校验（`path.dirname` 必须严格等于 `data/sessions`，否则抛 `Invalid session directory`），防止路径穿越误删。

## 6\. 数据模型

### 6\.1 SQLite

**文件**：`data/booth.sqlite`（WAL 模式）

```SQL
CREATE TABLE IF NOT EXISTS records(
  kind TEXT, id TEXT, json TEXT, PRIMARY KEY(kind, id)
);
```

单一的 key\-value \+ JSON 表，`kind` 区分实体：

|**kind**|**id**|**内容**|
|---|---|---|
|`style`|模板 ID|完整 Style 对象（含提示词）|
|`retired-style`|模板 ID|已下线模板快照|
|`session`|UUID|会话（含私有字段）|
|`frame`|会话 ID|相纸与文字（**与 session 分表**，避免慢生成覆盖后续选择）|
|`order`|UUID|订单|
|`print`|`sha256(session:image)`|打印任务|

**Session 公开字段**：`id, styleId, styleName, purpose, orientation, clothingMode, status, mode, createdAt, expiresAt, images[], error?, elapsedMs?, requestId?, promptVersion?, pickupUrl?`
**Session 私有字段（绝不返回前端）**：`photo, files, snapshot, token, tokenHash, retentionMs`

**安全设计**：`POST .../frames` 与 `session` 分表存储的原因写在代码注释里——「Store decoration separately so a slow generation job cannot overwrite a later selection\.」

### 6\.2 目录结构

|**路径**|**内容**|
|---|---|
|`data/booth.sqlite`\(\+`-wal`,`-shm`\)|全部记录|
|`data/sessions/<id>/photo.jpg`|归一化后的原图|
|`data/sessions/<id>/<imageId>.jpg`|成片（无缩放）|
|`data/sessions/<id>/<imageId>-preview.jpg`|预览（最长边 1600）|
|`data/examples/<uuid>.jpg`|管理员上传的示例图|
|`data/print-jobs/<uuid>.jpg`|待提交合成图（mode 0600，提交后删除）|
|`data/printer-settings.json`|打印机设置（原子写，0600）|
|`data/admin-auth.json`|管理员密码哈希（0600，目录 0700）|
|`data/generation-timing.jsonl`|生成计时日志（每行一条 JSON）|
|`data/instances/<uuid>/`|`BOOTH_FRESH_INSTANCE=1` 时的独立数据目录|

### 6\.3 图片处理参数

|**用途**|**缩放**|**质量**|**色度采样**|**元数据**|
|---|---|---|---|---|
|上传归一化|最长边 **3072**（不放大）|JPEG **96**|4:4:4|剥离 \+ 自动转正|

### 6\.4 计时日志字段

成功路径：`sessionId, mode, taskStart, uploadBytes, outputSize, model, providerMs, providerImages[], writeMs, encodeMs[], savedBytes[], totalMs, status, requestId, completedAt`
`providerImages[]` 

单项：`requestStart, headersMs, bodyMs, decodeMs?, downloadMs?, responseBytes?, returnedBytes, requestId?`
异常路径：`status = 'aborted'`（附 `reason: missing|expired|status-changed`）或 `status = 'error'`

|照片 10 分钟删除|与「付款等待 \+ 打印排队」存在冲突窗口|
|无开机自启|断电/重启后需人工启动|
|无每日费用上限|存在 API 成本失控风险|
|无前端埋点|无法做转化率分析|
|13 项边框|无自定义边框能力|
|无搜索/收藏|63 款模板靠分类翻找|
|打印无出纸确认|「已提交」不等于「已出纸」|
|相纸尺寸未确认|现场打印规格仍是开放项|

### 9\.2 风险登记册

|风险|等级|应对|
|---|---|---|
|**重复计费**|高|幂等 \+ `unknown` 硬阻断 \+ 启动不重试 \+ `providerCompleted` 标记|
|**重复出纸**|中|`sha256` 主键 \+ at\-most\-once 状态机 \+ 重启恢复分级|
|**免费生图成本**|高|需明确付款后生成、或设定免费次数与预算上限【待定】|
|**清理与交付冲突**|中|支付/打印/取图期限需统一协调【待定】|
|**到账伪造**|高|顾客操作一律不作为到账依据，只认服务端验签回调|
|**相似度不达标**|中|提示词约束不等于保证；需真实成片人工验收|
|**IP 漂移**|中|建议为设备保留固定局域网地址|
|**驱动差异**|中|不预设选项存在，读不到就停止配置|
|**无人值守硬件故障**|中|异常时停止接受新付款，给已付款顾客凭证与处理入口|
|**人力依赖**|—|仍需人工补纸、补墨、处理卡纸|

|依赖|说明|风险|
|---|---|---|

|macOS CUPS|打印通道|驱动能力差异|

## 11\. 验收标准

### 11\.1 功能验收（Given / When / Then 摘要）

|\#|Given|When|Then|
|---|---|---|---|
|A1|待在机页|不做任何操作|封面每 6 秒切换；**不创建任何会话**；永不自动结束|
|A2|已选主题|点击「拍照」|3 秒倒计时后抓帧并进入确认页|
|A3|确认页|未勾选同意|「确认并生成」保持禁用|
|A4|已勾选同意|点「确认并生成」|上传照片 → 提交生成 → 进入等待页|
|A5|生成中|再次调用生成接口|返回 200 现状，**不产生第二次上游调用**|
|A6|状态为 unknown|用户尝试重试|服务端 409 拒绝，界面无重试按钮|
|A7|生成完成|修改相纸与文字|不重新生图；失败时阻断结算|
|A8|结果页|点「确认取图」|创建 990 分订单，进入支付页|
|A9|支付页|点「确认取图 →」|生成 64 位 token，显示二维码|
|A10|手机扫码|打开取图页|只能看到该 token 已购照片；不能访问本机接口|
|A11|同一张照片|重复点「打印照片」|只提交一次，第二次直接返回已有任务|
|A12|服务重启|存在 `submitting` 打印任务|标记为 `unknown`，**不自动重打**|
|A13|服务重启|存在 `generating` 会话|标记为 `unknown`，**不自动重试**|
|A14|生成完成|等待 10 分钟|照片、预览、相纸、取图凭证全部删除；订单记录保留|
|A15|体验中|空闲 120 秒|自动清屏回到待机页，并对会话发 `/end`|
|A16|局域网机器|访问 `/admin`|403 拒绝|
|A17|已登录管理员|闲置 10 分钟|自动锁定，界面清除敏感内容|
|A18|模板提示词含 `{{占位}}`|尝试开启该模板|拒绝并提示替换占位内容|
|A19|门店自定义过提示词|服务升级|**自定义内容保持不覆盖**；版本不重复自增|
|A20|已完成一轮体验|刷新页面|只恢复 `snap-round` 记录的会话，不请求全量相册|

### 11\.2 实机验收清单（必须人工完成）

1. 打开本机页面 → 开始 → 选主题 → 允许摄像头 → 确认实时取景与 3 秒倒计时拍摄。

2. 确认本人照片并提交 → 检查真实生成结果与用时。

3. 模拟支付 → 手机连同一 Wi\-Fi → 扫码打开相册并下载 → 检查手机相册中的照片。

4. 返回首页检查摄像头已停止，下一位看不到上一位的照片。

5. （打印）现场确认相纸后，点一次打印验证尺寸、边框、颜色与张数。

### 11\.3 营业验收清单（正式切换前）

真实支付成功与取消、生成成功与失败、实体出纸、缺纸与打印机离线、进程重启、支付通知延迟、店内手机扫码保存——**系统队列显示完成仍需核对实体出纸**。

**验收红线**：不以「安装成功」或「接口模拟通过」作为营业验收。

### 11\.4 样片验收标准（5 条）

1. **是不是本人**：比较脸型、眉眼位置、鼻口比例、年龄感、眼镜与发型。

2. **类型是否鲜明**：电影是夜景光色、商务是自然棚拍、3D 是明确立体材质。

3. **面部是否可用**：眼睛清晰、曝光自然、无明显磨皮/漂白/遮挡/形变。

4. **交付构图**：单人、完整头部肩部、足够留白、无多余文字与拼图。

5. **版本记录**：记录模型、完整 prompt、size、输入样本、耗时与用户评价。
