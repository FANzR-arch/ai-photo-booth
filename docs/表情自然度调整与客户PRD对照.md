# 表情自然度调整与客户 PRD 对照

日期：2026-10-01。

本次需求是收敛照片中过于夸张的表情，并参考客户提供的 PRD。客户文件是 Mac 运行实例的 v1.0 基线快照，其中的状态、建议优先级和路线图需要按具体事项核实；不等于本次要求把全部功能重新实现。

## 本次调整

原有提示词允许按主题设计动作和表情，部分导入场景同时要求灿烂露齿笑、睁大眼睛、O 形嘴或嘟嘴。这些要求容易把普通顾客的表情推向表演感。

- 所有模板的最终生成提示词统一补充自然表情规则，包括普通照片、定向场景和成人礼海报。默认嘴唇自然轻合，轻微笑意或平静神态；不强制露齿，不放大原照已有的轻微露齿笑。
- 眉眼放松，保留本人眼睛的自然形状与开合幅度。开心、惊喜和俏皮通过少量笑意、视线和原场景手势表达，不靠张嘴、瞪眼、抬眉或嘟嘴。
- 自然表情规则位于可编辑主题及换装描述之后，明确覆盖其中过大的表情幅度。后台自定义文字保持原样，但生成时同样应用此规则。
- 场景动作、手势、道具、服装选择、画幅和指定文字继续按原方案执行，合照逐人调整，不复制成同一种笑容。

| 场景 | 原描述 | 调整后 |
| --- | --- | --- |
| 成人礼、医生肖像 | 指定上排牙齿、开朗露齿笑 | 闭唇浅笑、眉眼舒展；职业神态亲切自然 |
| 金色生日、婚礼与胶片合照 | 灿烂露齿笑、张嘴惊喜 | 轻微笑意、温暖放松，保留互动动作 |
| 朱红婚照·俏皮 | 嘟嘴亲吻表情 | 嘴唇自然轻合，保留叉腰与轻微俏皮笑意 |
| 海岛·椰子 | 睁大眼睛、张嘴喊朋友 | 明亮放松的眼神、轻微笑意，保留捧椰子和指向镜头 |
| 海岛·惊喜 | 抬眉、睁大眼睛、O 形嘴 | 自然眉眼和轻松笑意，保留指向自己的手势 |
| 暖光暗调、镜面合照 | 指定可见上齿或露齿笑 | 自然轻合嘴唇、安静或轻松的神态 |

本次直接更新 15 款场景的主题提示词：`coming-of-age`、`doctor-classic`、`doctor-relaxed`、`doctor-folder`、`wedding-flash`、`film-street-couple`、`film-surf-couple`、`warm-low-key`、`birthday-gold`、`wedding-bride`、`wedding-groom`、`wedding-heart-couple`、`island-coconut`、`island-surprise`、`mirror-couple`。其中 5 款双人导入场景继续保持未启用，其余模板通过通用规则收敛表情。海岛·惊喜的卡片说明同步改为“指向自己、轻松笑意”。

| §3.2：职业形象专业、自然、不夸张 | 收敛医生场景的露齿笑，所有职业照追加自然幅度规则 |

| §11.4：身份、媒介、面部、构图、版本验收 | 补充表情幅度对照验收，实际成片仍需人工检查 |

阅读客户文件时还发现以下需要分清的事项：

- FR-06.1 中“前端只传照片和一个 prompt”需要校正。当前上传接口接收照片、画幅和服装选择，生成提示词由服务端根据会话中的模板快照拼装，前台顾客不能自由提交 prompt。
- §11.4 的“单人、无多余文字”不能直接用于所有模板。实际项目有合照，也有允许指定文字的海报与场景；验收应按实际人数与模板的文字规则判断。
- §0.2 报告手机取图暂时异常，§11.5 同时引用 LAN 接口成功的历史记录。接口响应成功不能证明客户现场手机可以保存照片，现场问题仍需单独复现。
- §1.5 说明当前不做开机自启，而 §10.3 又把自启列为建议需求；它属于后续范围选择。本次也不接入真实支付、预算上限、打印扩展或公网取图。

## 升级与维护

- `apps/server/generation-prompt.ts`：统一表情幅度，覆盖三种生成分支。
- `packages/shared/imported-scenes.ts`：从原始提示词导入时替换强表情描述，保留原始来源。
- `config/styles/styles.json`：当前场景提示词与版本。
- `config/styles/scene-quality-migration.json`：记录调整前的字段哈希，供已有 SQLite 数据升级使用。
- 客户 PRD 和原始场景提示词不改写；现有封面继续保留，封面不是此次调整后的成片验证。

运行中的服务需重启才加载修改。匹配旧内置版本的模板自动升级，自定义字段保留，已生成照片不重新生成。尚未提交生成的旧会话保留其主题快照，但新代码会在请求中追加自然表情规则。
