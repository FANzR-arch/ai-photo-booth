# 给客户 Mac 上 AI 的部署任务

请直接协助我在当前 Mac 上安装和联调「咔嚓！AI 拍照亭」，不要只给我一篇教程。我不熟悉 Mac；你能通过终端和文件工具完成的步骤请直接做，只有必须由我操作的登录、系统授权、密钥输入或物理设备动作才交给我，并说明具体窗口、按钮、输入内容和成功表现。

- GitHub 仓库：https://github.com/FANzR-arch/ai-photo-booth
- 目标分支：main。请先读取仓库 README-Mac.md，并按其中的当前脚本执行。
- 推荐项目路径：当前用户目录下的 `~/Applications/ai-photo-booth`。如果已经安装在别处，先确认并沿用现有目录，不创建重复实例。
- 客户提供的配置：MacBook Air M1（2020）、8GB、macOS Tahoe（首张截图为 26.2，后续现场 AI 报告为 26.6.2，以本机检查为准）；外接 UGREEN Camera 4K；EPSON L805 打印机。

## 第一步：确认你实际能执行什么

1. 确认你是否能在这台 Mac 上执行终端命令、读写项目文件，以及是否能操作浏览器。不要假装具有未提供的工具。
2. 如果只有聊天能力，没有本机执行工具，请立即说明，并引导我打开“访达 → 应用程序 → 实用工具 → 终端”。也可提示按 Command + 空格，输入“终端”并回车。一次只给一组短命令，等实际结果再继续。
3. 有工具时直接开始只读预检，确认实际 `sw_vers`、`uname -m`、当前用户、剩余空间、Git 是否可用，以及是否已有本项目运行。不要读取浏览器密码、钥匙串内容或其他项目密钥。
4. 若 `uname -m` 为 x86_64 但硬件是 M1，检查当前终端/AI 是否通过 Rosetta 运行。不要直接下载 Intel 运行环境；说明如何打开原生终端，或在确认可行后使用原生 arm64 子进程运行安装器。
5. Git 未安装时，可发起 Apple Command Line Tools 的正规安装，并告诉我系统弹窗如何点击。不要安装整套 Xcode 或无关工具；安装过程可能耗时，不能把尚未完成当作成功。

## 第二步：安全拉取仓库

如果 `~/Applications/ai-photo-booth` 不存在，依次执行：

```bash
mkdir -p "$HOME/Applications"
git clone --branch main --single-branch https://github.com/FANzR-arch/ai-photo-booth.git "$HOME/Applications/ai-photo-booth"
cd "$HOME/Applications/ai-photo-booth"
git rev-parse HEAD
```

如果路径已经存在：

- 确认是这个仓库，查看当前分支和 `git status --short`，检查 `.env`、`data/` 是否存在，但不要输出它们的内容。
- 如果已有运行实例，先等待当前体验和生成完成，再正常停止本项目。不要终止其他 Node 程序。
- 有配置或数据时，按 README-Mac.md 的更新步骤先做受限备份，保留现场修改，再 `git pull --ff-only origin main`。如果分支不同、存在修改或发生冲突，先报告具体情况，禁止强制覆盖。
- 如果目录属于其他项目，停止并说明，不移动或删除它。

如果 GitHub 返回无权限或登录要求，说明需要有仓库访问权限的 GitHub 账户。已有 GitHub CLI 时可用其标准浏览器登录流程；否则引导用户使用当前可用的正规认证方式。不要要求我在聊天里粘贴密码、Token、SSH 私钥，不要把仓库改成公开，也不要把访问令牌拼进 clone URL。

## 第三步：安装 Mac 环境

在首次安装的项目目录执行：

```bash
bash install-mac.command
```

该脚本在项目内准备固定版本 Apple 芯片 Node，核对官方 SHA-256，按锁文件安装 Mac 依赖，构建页面并检查图片处理、SQLite。没有 API 密钥也能安装并进行免费联调。

- 不要从 Windows 复制 node_modules、runtime 或真实 .env。
- 不需要 sudo，不修改系统 Node，不安装 Homebrew，不关闭 Gatekeeper、SIP 或防火墙。
- 下载或 npm 失败时，先区分网络、权限、校验和依赖错误；保留简洁错误与失败域名。不要无依据反复重试、切换未知下载镜像或跳过 TLS/哈希校验。
- 如果系统阻止具体可执行文件，请报告原始提示，先核对来源和校验，再指导正规授权；不要递归移除整台电脑的隔离标记。
- 重复安装不会覆盖 .env、data；已有完成标记时安装器会退出准备步骤。如果是更新，使用 README-Mac.md 的 `prepare.sh --update` 流程，不能仅 pull 后假定页面已更新。
- 记录 Git 提交、Node 版本、安装路径、依赖加载与构建结果。

## 第四步：先运行免费联调

运行：

```bash
bash "$HOME/Applications/ai-photo-booth/mac-booth.command"
```

菜单输入 `1` 并回车。这会使用独立数据和随机端口启动模拟图片模式，**不会调用付费生图 API**。读取终端实际打印的网址并打开，不要猜成固定 4377。

若你不能操作交互式菜单，但可以在项目目录保持一个终端会话，也可以执行等价命令：

```bash
PATH="$PWD/runtime/bin:$PATH" GENERATION_MODE=demo BOOTH_FRESH_INSTANCE=1 BOOTH_OPEN_BROWSER=1 PICKUP_BASE_URL= NODE_ENV=production /usr/bin/caffeinate -i "$PWD/runtime/bin/node" --import ./node_modules/tsx/dist/loader.mjs apps/server/index.ts
```

请保持服务会话存活并记录如何返回该终端。不要仅启动一个会随工具退出而终止的子进程，就声称服务持续可用。当前脚本防止闲置睡眠，但不能保证合盖、断电、注销或重启后继续工作。

浏览器建议用 Chrome。自动打开的默认浏览器不是 Chrome 时，可打开 Chrome 并粘贴实际 localhost 地址，不必改系统默认浏览器。

## 第五步：检查外接摄像头、页面和取图

1. 启动后保持在拍照首页，不要自动跳到后台。需要配置时，由我主动点击首页“设备设置”。首次先通过本机菜单选 5 设置管理员密码，输入不回显；密码不要发到聊天中。解锁后台后，在“拍照摄像头”打开预览、选择 UGREEN、确认画面并保存。此选择只对当前浏览器与网址生效；联调端口改变或切换正式端口后需重新设置。
2. 系统没有授权时，引导我打开“苹果菜单 → 系统设置 → 隐私与安全性 → 摄像头”，开启 Chrome 权限。如果提示需要重新打开 Chrome，先说明对当前页面的影响。
3. 验证实际画面来自外接摄像头，不是 Mac 内置摄像头。可请现场人员把手放在外接镜头前确认，不要仅凭设备列表判定。
4. 在取得现场拍摄者同意后试拍，检查取景、方向、清晰度、倒计时、照片确认、模拟生成、相纸文字编辑、模拟解锁与取图页；没有现场配合时明确标为待验证，不伪造硬件结果。
5. 实际照片不要提交到 Git、上传诊断服务或发给开发者。优先报告操作结果；演示图不能作为真实生图质量证据。
6. 手机取图当前必须同一 Wi-Fi。用实际手机验证需要现场人员配合，不要拿电脑打开成功代替手机验证。若提示本地网络权限，针对需要的程序授权，不关闭防火墙整体防护。
7. 免费联调网址可能使用随机端口；退出后再启动会变，不要把它当作正式固定二维码。

## 第六步：读取打印信息，为后续自动打印接入做准备

执行只读检查：

```bash
lpstat -p -d
```

从输出得到实际的 EPSON 队列名后，再运行下面命令，将占位内容替换为已确认的队列名：

```bash
lpoptions -p "实际的队列名" -l
```

记录实际队列名、可用纸张规格、无边距及方向相关选项。若驱动不返回选项，说明限制，不编造支持能力。通过系统设置“打印机与扫描仪”补充确认驱动名称和队列状态。

询问现场人员目前装的相纸尺寸、希望每次打印几张，以及横竖照片采用裁切还是留白。纸张上未写明尺寸时不要猜。用户已确认系统打印可用，无须反复打印消耗耗材。

应用打印尚未开发：不要直接改业务代码、安装未知打印桥或伪装成自动打印已完成。当前阶段只收集接入所需信息。
