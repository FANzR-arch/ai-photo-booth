# 咔嚓 AI 拍照亭｜甲方需求对照与更新规划

更新：2026-10-02 · v1.4 简版

**目标：先在甲方现有设备把 Demo 跑顺，再接真实支付，最后评估新设备与本地算力。** 以下是建议推进顺序；具体决定直接在对话中确认，再更新本文。

## 需求与安排

| 编号 | 甲方需求 / 意向 | 当前状态与下一步 |
| --- | --- | --- |
| REQ-01 | 先把 Demo 跑顺 | 在甲方 Mac 上完成拍照、模拟付款、生成、打印与手机保存的整轮体验。 |
| REQ-02 | 表情自然，照片像本人 | 提示词已在本地收敛；甲方设备更新后，用医生、海岛新样片确认效果。 |
| REQ-03 | 先手动触发打印，后续自动打印 | 本地已加付款约束、“正在打印”提示与防重复提交；实体出纸待现场验收，自动打印后续接入。 |

## 推进顺序

1. **Demo：REQ-01–06，并验证 REQ-07 的顺序。** 用模拟支付跑通先付款再生成；补齐原片手机保存与手动打印状态，同时验收表情、颜色和视觉。
2. **商业化：REQ-07、REQ-03。** 接真实收款和自动打印，补齐重复操作、断网、生成失败、打印异常及退款 / 补打处理，明确交付期限。
3. **设备与算力：REQ-08–09。** 按甲方提供的资料独立评估，通过实测后再决定采用范围。

本轮对话已确认：**拍照确认 → 套餐付款 → AI 生成 → 电子图与纸质打印交付。** 手机交付包含拍摄原片；打印先手动触发，后续在成片就绪后自动触发。

本地 Demo 已加入付款前禁止生图 / 打印、手机原片交付、打印状态与明亮界面；现场验收、真实收款与自动打印仍待完成。

当前生成照片保留 10 分钟，付款、下载不会延期；商业化时需协调支付等待、打印排队和故障交付。

## 验收重点

- **照片与页面：** 甲方确认新样片像本人、表情自然，页面明亮且操作清楚。
- **现场 Demo：** 未付款不能生成或打印；付款后实际出纸，手机能保存拍摄原片与套餐电子图；打印开始后显示“正在打印”，重复操作不重复提交，下一位看不到上一位照片。
- **正式营业：** 真实到账才放行交付；订单、退款和异常可查询处理。模拟支付和系统接收打印任务不能作为营业通过依据。

本地提示词修改尚未取得甲方现场验收；新设备与算力也尚未接入。后续按需求编号更新进度。
