# 咔嚓！AI 拍照亭

现场设备版本：真实 Seedream 生图、相纸与文字编辑、手机扫码取图。**当前实现仍为模拟支付，不会实际扣款。**

当前优先完成桌面一键启动、网页密码与 API 配置，收费功能暂缓，不设开机自启，手机使用店内 Wi-Fi 取图。当前缺口、待定配置和实施顺序见 [无人值守上线](docs/无人值守上线.md)。

## 启动

**Apple 芯片 Mac：**请使用 [Mac 安装说明](README-Mac.md)；交给设备上的 AI 执行时，可直接提供 [完整部署提示词](docs/Mac-AI-部署提示词.md)。Mac 安装后双击桌面「启动拍照亭.command」，网页设置密码、填写 API 并保存后立即生效；已接入 [Mac 点击打印](docs/Mac直接打印.md)，相纸配置与实体出纸需现场确认；真实支付和公网取图尚未接入。

1. 首次使用：安装 Node.js 24+，复制 `.env.example` 为 `.env`，填写 Seedream 密钥和模型。
2. 双击 `启动拍照亭.cmd`。源码目录会安装锁定依赖并构建；便携包使用自带 Node。
3. 在电脑打开 [拍照亭](http://localhost:4377)，首页“设备设置”可主动进入 [/admin](http://localhost:4377/admin)。首次在网页输入至少 8 位密码，点击“设置并解锁”；程序启动默认打开拍照首页。手机连接同一 Wi-Fi 扫码取图。

正式入口固定使用 `PORT`（默认 4377）与 `data/`。重启会保留主题设置、订单与未过期照片；相同模式重复启动会打开已有服务。请勿删除 data，或改变设备局域网地址后仍使用旧二维码。

`start-demo.cmd` 仅用于本地流程测试，使用独立数据和随机端口，不调用 Seedream。它的图片不代表 AI 生成效果。

## 当前能力

- 63 款启用模板，按内容分为人像写真（13）、职业形象（5）、生日纪念（6）、婚礼写真（2）、亲友合照（10）、旅行日常（11）、创意艺术（16）；每款只在一个分类出现，数量随启用状态更新。自定义模板显示在“其他模板”，空分类隐藏。另有城市、品牌两款待配置模板，以及按用户要求暂留的 5 款双人新模板。
- 拍照/上传，竖版 3:4 或横版 4:3，单张生成；相纸与文字编辑不重新生图。
- 确认照片时选择“保留原服装”（默认）或“按主题换装”。两种选择都允许按主题重新设计站姿、坐姿、头部朝向、手势、表情及合照站位；人脸一致性优先，保留本人五官、年龄感与实际人数。原服装的款式与配色保留时，衣料随新动作自然变化。各主题动作写在视觉提示词内，换装搭配可在工作台独立编辑；实际效果以生成结果为准。
- “生日纪念”中的「你好，我的18岁」成人礼海报，按用户提供的完整提示词生成。该模板固定 2:3 竖版（默认 1216×1824）、深蓝换装，并允许整理发型、调整姿势与表情；指定中英文和银白金属标题直接生成在图片内，默认无边框。保留本人身份与年龄感，封面为 Codex 内置生图制作的虚构人物样片，未将用户照片加入公共素材。
- 原照片免费保存；生成照片显示单张 ¥9.90，确认取图后生成下载链接；当前解锁逻辑仍为模拟支付。
- 生成任务和装饰设置可刷新恢复；同一设备一次处理一个生成任务；上游结果未知时不重复提交。
- 各步骤可返回；本轮照片库支持找回原图、生成结果和已购取图码，结束体验后隐藏，刷新可恢复仍在进行的本轮。
- 新照片从生成完成起保存 10 分钟，付款、查看和下载不延长；照片库及手机取图页显示倒计时，到期自动删除。拍照与工作台仅限本机访问，手机仅能查看取图凭证对应的已购照片。

密钥只保存在本机后端。新制作的 Windows 包只带空白配置模板，不复制密钥和顾客数据。

照片分类与排序统一维护在 `packages/shared/photo-categories.ts`。页面分类独立于历史会话的用途标识；选择模板时仍映射到原有拍摄指导和相纸推荐，已有照片及会话不需要迁移。

[运行与部署说明](docs/部署建议.md) · [API 配置](docs/DEMO_API.md) · [当前验证状态](docs/DEMO_STATUS.md)

提示词由 apps/server/generation-prompt.ts 组合人脸身份、主题视觉、动作表情、服装选择、人体结构和输出比例；config/styles/styles.json 的 prompt 描述画面、动作与对应媒介的质量要求，outfitPrompt 仅在换装时发送。写实主题强调合照对焦、自然皮肤、衣料与光影衔接；艺术主题分别约束像素网格、颜料、纸张或手作材质。画幅以用户选择为准，取景随主题动作安排，不受原照姿势及裁切范围限制。内置默认尺寸使用 HQ：3:4 为 1296×1728，4:3 为 1728×1296，2:3 为 1216×1824，4:5 为 1344×1680，3:2 为 1824×1216；这些均已通过当前 Seedream 5.0 pro 实测。提示词不等同于提升像素分辨率。

升级只替换匹配旧版本哈希的内置提示词（包括 quality-migration.json），保留工作台自定义内容及已有照片。主题质量改动用于升级后新提交的生成；已生成照片及其主题快照保留，成片效果仍需真实生成对照验证。

pose-migration.json 分别匹配旧视觉提示词和换装提示词的哈希，清理“保持原姿态”等旧约束；两类自定义编辑独立保留，已有照片不重新生成。

成人礼模板通过 generationPreset=coming-of-age 单独执行其海报提示词，不附加普通照片的禁字和可选服装规则。工作台直接编辑该模板的“主题视觉提示词”即可修改海报造型、服装与文字；outfitPrompt 不单独附加。复杂汉字和金属字效果仍需实际成片验收。

## 新场景与质感验证（2026-09-29）

17 份源提示词保存在 `docs/sources/prompt-import-2026-09-29/单张照片提示词/`。`packages/shared/imported-scenes.ts` 负责源编号、分类和适配：只以用户照片作为身份参考，场景由文字描述，清理不存在的样片引用和强制长发。成人礼沿用同一 ID 更新，没有重复新增。其余场景使用 `generationPreset=directed-portrait`，固定场景画幅、默认主题换装，仍可选择保留原服装；场景指定的文字、帽饰和道具允许生成。

`packages/shared/appearance-styling.ts` 负责造型自动适配：根据参考人物的可见呈现选择男装、女装或中性搭配，不增加性别识别接口、不输出或保存性别标签。派对、婚礼与海岛场景去掉写死的男女造型要求，保留原发长、人脸与动作；“保留原服装”仍覆盖模板换装要求。婚礼两款单人模板按动作命名为“俏皮”和“回应”，ID 不变。模型的自动适配结果仍需成片检查。

12 张独立封面由 Codex 内置生图生成。原 PNG、提示词与 SHA-256 在 `docs/sources/prompt-import-2026-09-29/covers/`，网页 WebP 在 `assets/examples/scene-*.webp`。5 款双人模板默认关闭，待使用两人合照实测后再启用。

`apps/server/photo-quality.ts` 统一上传与输出编码：上传最长边 3072 / JPEG 96 / 4:4:4，自动转正并去除元数据；成片保留上游像素尺寸，JPEG 97 / 4:4:4；预览最长边 1600 / JPEG 92 / 4:4:4，均不放大小图。`scene-quality-migration.json` 逐字段匹配旧值哈希，独立保留自定义提示词、封面、尺寸和开关，不修改历史生成快照。

场景迁移支持同一字段的多个已发布版本哈希，名称与提示词独立升级；工作台的自定义名称、提示词和启用开关继续保留。`scripts/import-scenes.ts` 更新配置时累积旧版本哈希，重复运行不增加版本号。

真人测试由 `scripts/test-imported-scenes.ts` 显式 `--live --source=...` 执行，不自动重试已提交任务；`--code=06,08 --revision=v2` 可记录明确的新版本评测。评审资料保存在被 Git 忽略的 `docs/evidence/seedream-scenes-2026-09-29/`，不进入网页公共目录，也不适用顾客照片的 10 分钟清理。12 个单人模板全测，成人礼补 1 张尺寸对照，2 款补发型修订复测，共 15 张成功结果。不能据此保证每次人脸、汉字或动作都完全一致。

使用另一张参考照片时必须传入独立的 `--run=<批次名>`，在 `docs/evidence/` 下保存；同一批次禁止更换输入照片。测试直接读取内置配置并记录模板 ID、版本、实际提示词和原图校验值。`node scripts/scene-review.mjs --run=<批次名>` 汇总已成功结果，生成总览图与本地评审页。
